# 一期方案总览：独立知识服务与模型接入平台

更新：2026-09-08。以下是修订后的目标，不表示功能已经全部实现。边界以 [ADR-002](ADR-002-知识服务一期独立.md) 为准。

## 项目职责

| 项目 | 一期目标 | 当前状态 |
| --- | --- | --- |
| Opsark_knowledge | 自己的管理 Web/鉴权、知识 Key、上传、审核、版本、检索和 Worker | 独立管理入口与后端已实现；长期数据/索引目标待补 |
| Opsark_admin | 多供应商配置、模型映射、模型用户 Key、实际转发和监控 | 已实现兼容 Chat Completions 的开发版；真实上游待验收 |
| Opsark_core | 独立配置两类接口，调用模型、手动上传任务，接入知识引用 | 知识设置和上传已有；检索开关仅预留 |

目标调用关系：管理员分别登录两个系统；core 直接调用知识公共接口，也独立调用模型接口。知识与模型调用互不依赖对方服务在线，不跨库访问。

Admin → knowledge 代理已退役。模型对外地址为 http://127.0.0.1:8001/v1；4000 是可选 LiteLLM 实验模板，与新平台 Key 不通用。具体支持范围见 [开发版说明](独立系统开发版使用与验收.md)。

## 模型接入：一期必做

- 多家第三方 API 配置：协议、base URL、受保护的上游 Key、超时、测试、启停。
- 对外模型别名映射到指定供应商/真实模型，维护能力和参数兼容信息。
- 用户模型 Key：管理员分配归属、有效期、撤销、可用模型、限流；不要求先做公众注册。
- 真正提供统一接口并转发普通 JSON 与 SSE 流式响应，兼容 core 现有非流式调用。
- 监控调用者、渠道、模型、请求量、成功率、状态、耗时、Token 用量和脱敏错误。缺失 usage 标为未知，不当作零。
- 上游 Key 不交给用户、不写日志；默认不存请求/响应正文。用量监控不是财务账本。

允许复用成熟网关作为内部引擎，但控制台链接不能替代上述业务。第一期不训练/部署模型，不要求 GPU。

## 知识一期与长期约束

保留结构化来源入库、持久任务、模板草稿、人工审核、不可变发布版本、切片检索。当前不调用大模型整理，上传不自动进入检索范围。

一期补独立管理页面/鉴权、拒绝审核/分页；落实资料归属权限、来源关系、适用软件版本/验证时间、索引构建配置绑定。AI 整理和多来源自动合并后续开发。

删除知识文档会清理版本与切片，但来源正文需另外删除；备份和保留期限需单独约定。生产前验证 PostgreSQL、数据库侧检索、中文效果、隔离、恢复和删除。当前 Python 扫描上限 5 万片段不是性能验收结论。

## core

知识 URL、Key、目标库和开关独立保存；Key 在钥匙串。上传须脱敏预览并人工确认，重试保留原正文和幂等标识。关闭上传暂停发送/状态查询，不删除历史。

检索开关仅保存偏好，尚未接 Agent；后续引用不能覆盖执行授权或实时验证。见 [core 说明](../../Opsark_core/docs/KNOWLEDGE_UPLOAD.md)。

## 范围

公众注册、充值/支付/财务账本、套餐、完整团队体系、长期记忆、文件解析/抓取、本地推理和复杂智能路由后续单独设计。基本模型 Key/转发/监控属于一期；开放多用户前的安全隔离也不能推迟。

见 [实施计划](一期实施计划与验收.md) 和 [知识长期演进](../../Opsark_knowledge/docs/知识服务长期演进.md)。
