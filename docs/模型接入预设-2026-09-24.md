# 模型接入预设（2026-09-24）

## 本批范围与实施顺序

1. 建立有版本的服务端预设目录：DeepSeek、千问、OpenAI API（ChatGPT 系列），保留自定义。
2. 路由绑定预设；旧路由迁移为 `custom`，不推断供应商、不改地址或密钥。
3. 按预设转换思考开关和输出 Token 字段，保存及调用前校验；提供不调用上游的参数预览。
4. 管理页面提供供应商地址模板、模型选择、预设说明、参数预览和自定义入口。
5. 覆盖迁移、API、参数转换、能力降级、前端交互的离线测试。

本批只支持当前网关的 Chat Completions 协议。Responses 的请求、事件流、用量和状态语义不同，不通过改字段名冒充兼容。没有配置真实凭据、迁移生产数据库或调用付费接口。

## 规则

- 优先级：预设默认值 < 供应商默认值 < 调用参数 < 路由强制参数。
- 不默认写死输出 Token，保留 Core 各阶段的预算及现有官方调用限额。
- 预设仅适用于目录列出的模型；其他模型选择自定义，不根据名字猜测能力。
- DeepSeek Chat 与本批 Qwen Plus/Flash 预设不支持严格 Schema：返回 `UPSTREAM_SCHEMA_UNSUPPORTED`，由 Core 有界降级到 `json_object`，仍由 Core 校验 `steps` 等业务结构。Admin 不自行重试、不补空步骤、不伪造成功。
- 已有自定义路由仍透传原参数；额外识别 DeepSeek 的 `This response_format type is unavailable now`，但不把认证、限流、普通服务不可用或 Schema 定义错误误判为能力缺失。
- 千问默认关闭思考，以兼容本批模型的 JSON Output 和当前非流式 Core；显式开启思考时检查流式及格式限制。
- Qwen Plus/Flash 的 `max_tokens` 不包含思维链；只有关闭思考时才允许从 `max_completion_tokens` 转换，避免把总预算悄悄放宽为仅回答预算。新千问型号使用独立预设，不套用此规则。
- OpenAI 本批预设 GPT-4.1 / GPT-4.1 mini（非推理模型），不是所有 GPT 型号的通用规则。关闭思考属于无操作，开启思考则明确拒绝。
- 所有预览只处理参数；不接收或回显 API Key，不探测上游，不扣费。

## 官方依据

- [DeepSeek Chat 参数](https://api-docs.deepseek.com/api/create-chat-completion/)：本批目录 `deepseek-flash`、`deepseek-v4-pro`，Chat 输出类型为 text / json_object。
- [DeepSeek JSON Output](https://api-docs.deepseek.com/guides/json_mode/)：提示词需要 JSON 指令和目标示例；空内容、截断仍需调用方处理。
- [DeepSeek Responses](https://api-docs.deepseek.com/zh-cn/guides/responses_api/)：这是独立协议，其 Schema 能力不代表 Chat 端点支持 Schema。
- [千问 OpenAI 兼容接口](https://help.aliyun.com/zh/model-studio/qwen-api-via-openai-chat-completions)：HTTP 参数 `enable_thinking`，temperature 小于 2；默认地址模板使用北京地域，其他地域应明确修改。
- [千问结构化输出](https://help.aliyun.com/zh/model-studio/qwen-structured-output)：本批 `qwen-plus`、`qwen-flash` 的 JSON Object 使用非思考模式；不能泛化其他型号的 Schema 能力。
- [OpenAI Chat 参数](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)：使用 max_completion_tokens。
- [GPT-4.1](https://developers.openai.com/api/docs/models/gpt-4.1)、[GPT-4.1 mini](https://developers.openai.com/api/docs/models/gpt-4.1-mini)：支持结构化输出，输出上限 32768。

## 发布注意

先备份数据库，再随 Admin 发布运行 Alembic `upgrade head`（新增 0010）；本次开发不对运行中的数据库执行迁移。只升级 Admin，不要求改变 Core 请求协议。新预设需管理员主动选择保存；既有路由不会自动切换。

## 使用与验收

1. 在“供应商 API → 新增供应商”选择地址模板，确认地域/代理地址后填写自己的 API Key。
2. 在“模型路由 → 新增/编辑”选择接入预设、真实模型和已配置的供应商。对外模型别名保持独立。
3. 展开可选参数，使用“预览参数（不调用模型）”查看配置合并及转换结果，再保存。
4. 不在目录中的模型选择“自定义模型”。该入口不是任意协议或任意请求体透传；仍遵守网关已有参数白名单、授权和用量限制。

本批不提供自动上游重试、自动切换供应商或自动调整地区。JSON Output 的空内容、截断、缺少业务字段仍由 Core 原有修复/验收流程处理；预设不能保证所有任务都成功。

本地验证入口：

```sh
.venv/bin/pytest -q
node --test web/tests/modelPresetForms.test.mjs
node scripts/smoke-model-presets.mjs
```
