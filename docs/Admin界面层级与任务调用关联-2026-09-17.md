# Admin 界面层级与任务调用关联

## 界面组织

沿用现有 Vue 3 和管理台配色，按“列表定位、详情处理、弹窗编辑”重组，不再把统计、配置和详情全部堆在首页。

| 入口 | 列表层 | 详情与操作层 |
| --- | --- | --- |
| 用户与额度 | 用户列表、注册与模型策略、待核对调用三个分区 | 独立用户详情：额度/调用概览、流水、会话、查看任务与调用 |
| 调用监控 | 调用请求 / 任务视图；服务端筛选与分页 | 任务调用按时间升序；请求弹窗展示关联、用量、错误及可用快照 |
| 系统 Skill / 工具管理 | 可搜索目录；发布历史单独分区 | 单项编辑弹窗、发布弹窗、历史预览；关闭保留本页草稿，保存不等于发布 |
| 联系与反馈 | 工单列表与状态筛选 | 联系设置弹窗；工单详情分为内容、诊断日志、处理回复；可跳转用户和关联任务 |
| 版本管理 | 发布记录列表 | 发布新版本弹窗、版本详情、撤回 |
| 供应商 / 模型路由 / Key | 保留已有紧凑列表 | 保留既有详情和编辑抽屉 |

用户详情与任务详情是列表页面内的独立视图，有明确返回入口；请求和编辑使用原生模态框。当前不提供详情深链接或跨刷新恢复导航状态。

## 关联链路

Core 使用已有应用级 `_log` 上下文。Rust 在准备模型请求时提取白名单字段，**只向已校验固定源站的官方账号网关**发送关联头，不向 BYOK 发送任务遥测。Admin 转发给供应商时也不透传这些头。

| 请求头 | 持久化字段 |
| --- | --- |
| `X-Opsark-Task-Id` | `task_id` |
| `X-Opsark-Round-Id` | `round_id` |
| `X-Opsark-Step-Id` | `step_id` |
| `X-Opsark-Phase-Index` | `phase_index` |
| `X-Opsark-Operation` | `operation` |
| `X-Opsark-Client-Request-Id` | `client_request_id`，对应 Core 本地日志 requestId |

标识限制为 128 字符以内的 ASCII 字母、数字和 `._:-`，以字母/数字开头；阶段索引为 0–999999。调用类型为 plan、stage_decision、requirement、model_check、summary、review、other。步骤、轮次或阶段必须同时带任务标识。传输重试保持同一个逻辑请求 ID，不冒充多次独立模型执行。

`user_id` 只取服务端已认证会话，客户端不能指定所属用户。任务按 **用户 ID + task_id** 分组；同一用户的不同登录会话可归入同一任务，不同用户的同名任务不合并。独立模型 Key 按 **Key ID + task_id** 分组，不把自由文本 owner 当成注册用户。

任务标识是客户端上报的排障标签，不是所有权证明，不参与授权。关联标签不包含服务器 ID、主机地址、完整任务标题或任务描述。

## 监控能力与边界

- 服务端支持邮箱、调用方、任务 ID、Admin/Core 请求 ID 搜索；精确用户/模型/供应商过滤；状态、时间范围、关联状态过滤；20/50/100 条分页。界面提供除供应商外的上述常用过滤项，供应商名称在请求详情显示。
- 统计覆盖全部筛选结果，而非当前页；显示成功/失败/进行中、已知输入输出 Token、用量未知请求数。未知用量不是 0，接口成功不代表任务成功。
- 请求详情显示双请求 ID、用户、任务、轮次、步骤、阶段、类型、供应商、状态、HTTP、错误码、耗时、用量，可继续跳转用户或任务。
- 用户官方调用和独立模型 Key **统一由 Admin 网关直接采集请求输入、模型输出及关联元数据、用量**，无需反馈上传才能查看正文。`MODEL_CALL_CAPTURE_ENABLED` 默认 `true`，显式关闭时新调用不保存正文；已存快照仍按保留期清理。正文经过凭据脱敏、加密后仅在管理员请求详情返回；列表、统计、用户用量/请求状态接口和查看审计不返回正文。反馈日志仍用于补充模型请求以外的本地执行信息，不自动上传本地日志。
- 默认保留 7 天，`MODEL_CALL_RETENTION_DAYS` 限定 1–90 天；输入和输出每侧最多 64 KiB，超限提示截短，不影响实际模型请求或响应。访问令牌、刷新令牌、已知供应商 Key 和常见凭据模式会脱敏，不采集 HTTP 请求头或认证 Cookie。自动脱敏不能保证移除全部业务敏感信息；部署时需同步用户可见的数据使用说明。历史未采集正文无法补回，正在执行、过期、关闭采集或保存失败时显示无可用正文。
- 单次请求详情读取新增 `model_call_viewed` 审计，记录操作者、关联标识和快照是否可用，不写入正文或令牌。
- 当前展示进入模型调用记录的已受理请求；前置鉴权、参数校验、限流、余额预留等拒绝不保证产生调用记录。这不是全站 HTTP 访问日志，也不是完整任务执行日志。
- 未经过 Admin 的 BYOK 调用不可观测。旧客户端或模型测试没有任务标签时显示“未关联任务”，不猜测历史任务或任务最终状态。
- 旧 `GET /api/admin/v1/calls` 保留裸数组兼容。新版使用 `/api/admin/v1/call-monitor/requests`、`/tasks`，返回 `{items,total,page,page_size}`，requests 另含 summary；详情继续使用 `/api/admin/v1/calls/{id}`。全部要求管理员会话。
- 工单过滤针对接口已加载记录，不声称完整历史搜索；流水与异常预留维持原有读取上限。

## 部署顺序

本轮新增迁移 **`0009_call_correlation.py`**：新增 nullable 关联字段与索引，仅通过已有 `model_reservations` 的可靠关系补齐历史官方调用 user_id；不从 owner 猜用户，不伪造历史任务 ID，不删除旧调用。

1. 停止写入，备份并验证数据库可恢复；不要直接复制仍有写入的 SQLite 文件冒充一致备份。
2. 在 Admin 已配置环境执行 `python -m alembic upgrade head`，当前升级到 `0009`。
3. 在 `Opsark_admin/web` 执行 `npm run build`，部署前后端并重启 Admin，刷新浏览器。
4. 重新编译/启动 Core 桌面 Rust 进程或发布新版安装包；仅刷新 Core 前端不能加载新请求头逻辑。先部署 Admin，再更新 Core。
5. 用受控账号的新任务验证用户详情 → 任务与调用 → 任务 → 请求详情，并与 Core 本地日志 requestId 对照。

开发期间只迁移临时 SQLite 数据库，没有修改业务库、生产配置或远端仓库，没有调用真实付费模型、真实 OAuth 或钥匙串。生产 PostgreSQL 和真实桌面端到端仍需部署环境验收。

同日追加的官方调用正文采集复用已有 `model_call_details` 表，**没有新增迁移，也不需要为此重新编译 Core**。若已部署上述关联版本，只需确认 `MODEL_CALL_CAPTURE_ENABLED=true`，重新构建 Admin web 并重启 Admin；从下一次新调用开始保存，已在途或历史未采集调用不补录。未部署关联版本的仍先完成 `0009` 升级和 Core 更新。
