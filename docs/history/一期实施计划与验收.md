# Opsark_admin 第一期实施计划与验收

更新：2026-09-06。当前状态：设计文档已编写；下列开发任务均未开始。

## 1. 实施原则

admin 和 core 分仓库、分部署、分验收。先让 admin 通过合成记录与契约测试独立可用，再安排 core 的小范围适配。模型接入沿用 core 现有配置流程；知识上传与检索是 core 后续新增任务。

一期基线：两个闭环都通过验收；付费、长期记忆等不作为本期完成条件。不能用“只有上传接口”替代审核发布，也不能用“普通聊天能返回文字”替代 Agent 模型兼容。

## 2. 建议目录（待开发时创建）

```text
Opsark_admin/
├─ README.md
├─ docs/                       # 本次已交付
├─ apps/admin-web/             # Vue 知识管理界面
├─ services/admin-api/          # FastAPI、领域逻辑、ORM、迁移
├─ services/admin-worker/       # 与 API 共享业务包，独立进程
├─ contracts/                  # OpenAPI 快照、合成请求样本
├─ deploy/                     # Compose、Caddy、网关配置模板
└─ tests/                      # 契约、集成、故障与检索评测
```

不 fork LiteLLM/RAGFlow 源码到项目中，不直接修改上游数据库；网关通过固定镜像和受保护配置集成。`deploy` 只保存密钥引用/占位模板，真实配置不进入 Git。

## 3. 里程碑与工作量

估算前提：1 名后端、1 名前端/集成人员，具备对应技术经验；部署环境和供应商测试额度可用。表中是总人日，不是两个人各自所需天数；约 22～33 人日，通常安排 4～5 个日历周并留缓冲。接口选型变化、复杂权限或额外文件格式需要重新估算。

| 阶段 | 任务 | 交付物 | 估算人日 | 前置 |
| --- | --- | --- | --- | --- |
| M0 选型验证 | 网关社区版 PoC、core 参数、Embedding/检索样本、版本与许可锁定 | 验证记录、依赖锁定清单、最终 ADR | 2～3 | 无 |
| M1 独立基础 | Compose、数据库迁移、管理员登录、知识 Key、公开/管理路由隔离、模型控制面 | 可独立启动的 admin 与受限模型接口 | 4～6 | M0 |
| M2 接收与审核 | 上传 DTO、脱敏检查、幂等、持久队列、模板草稿、编辑审核 | 可追溯的记录收件箱和草稿流程 | 5～7 | M1 |
| M3 发布与检索 | 文档版本、切片、Embedding、融合检索、引用、下架与删除 | 可发布并检索的知识库 | 5～7 | M2 |
| M4 联调与上线验证 | core 知识适配、模型协议回归、备份恢复、限流和压测、使用说明 | 两个闭环验收报告 | 6～10 | M3；模型联调可提前 |

M4 中 core 新增界面、上传队列、检索与引用约占 3～5 人日，已包含在该阶段估算中；如果先只交付独立 admin，可先完成 admin 验收，core 子任务单独排期，但不能将尚未完成的客户端功能标成已交付。

## 5. 必须通过的验收用例

| 编号 | 场景 | 通过标准 |
| --- | --- | --- |
| MOD-01 | core 填写平台 base URL/Key/model | `/models` 能精确匹配别名；需求理解、计划、复核与调整返回符合原协议的结果 |
| MOD-02 | 未授权模型/无效 Key/已撤销 Key | 请求被拒绝；上游不收到调用；客户端得到可识别 JSON 错误 |
| MOD-03 | thinking/JSON/输出上限 | 不支持字段已针对性适配；截断不能伪装为 `stop`；无上限请求也受网关上限保护 |
| MOD-04 | 核对重试 | 网关默认不叠加重试；观测实际发送次数，结构化修复调用可辨认 |
| MOD-05 | 上游 429/5xx/慢响应/usage 缺失 | 错误可定位，未泄露 Key；usage 缺失明确标记；不展示为正式账单 |
| MOD-06 | 管理边界 | 公共 `/v1` 无法触达 Key 签发/渠道管理接口；core Key 无管理员权限 |
| REC-01 | 合法记录上传 | 返回 202 后记录和任务已持久化，状态可查，管理端可见来源 |
| REC-02 | 同请求重复/并发提交/幂等过期重放 | 同一来源修订仅一条记录、一次有效任务；冲突返回 409 |
| REC-03 | 错误安装/库/scopes | 上传、查询和检索分别按授权拒绝；不会只检验一个 scope |
| REC-04 | 含 Authorization、私钥、明显密码的合成记录 | 拒绝且不持久化原敏感正文，错误/日志也不回显秘密 |
| REC-05 | Worker 中断/重启/重复认领 | 任务可恢复；不重复生成来源/文档/切片；达到重试上限后管理员可见 |
| KB-01 | 记录转草稿 | 有问题、环境、操作、证据、结论、来源；失败/部分完成不会变成成功案例 |
| KB-02 | 审核与检索 | 草稿不可检索；审核并索引成功后可检索，来源和版本正确 |
| KB-03 | 新版索引失败 | 旧发布版本仍可用，恢复后原子切换，无半套新旧切片 |
| KB-04 | 下架/撤权/删除 | 新检索立即不返回内容；直接引用请求也被拒绝或提示版本下架 |
| KB-05 | 中文与命令查询 | 达到下述固定评测集门槛，不只验收向量接口返回数字 |
| KB-06 | Embedding 超时 | 可降级为关键词并明确标记；不能把过期向量当作新模型索引 |
| SEC-01 | 恶意 Markdown/文档中的操作指令 | 页面无脚本执行；core 不将文档指令转成更高权限或自动执行 |
| OPS-01 | 备份恢复 | 在隔离环境恢复两个数据库、文件和所需解密配置，旧 Key/文档按预期有效或已撤销 |
| CORE-01 | 知识服务关闭/离线 | 不阻断原 SSH 执行与用户自配 API；上传错误和检索降级可见 |

### 检索质量门槛

准备 50 条人工标注查询：中文语义 20 条，路径/服务/错误码精确查询 15 条，环境或版本区别 10 条，无答案 5 条。样本只使用合成或明确脱敏资料。

- 有答案的 45 条中，至少 36 条在 Top 5 命中一条标注相关片段（Hit@5 ≥80%）。该指标不是全量 Recall@5。
- 所有返回结果均在请求授权与过滤范围内，跨库越权命中为 0。
- 引用文档 ID、版本及位置正确率 100%；无答案查询允许返回空，不要求编造“答案”。
- 固定测试机器与数据规模下，关键词检索 p95 目标 <1 秒；混合检索含远程 Embedding p95 目标 <3 秒。属于试运行验收目标，需记录供应商延迟，尚非对外 SLA。
- 响应正文严格遵守字符预算；core 另外验证模型 Token 预算与引用可见性。

### 模型兼容性特别注意

现有 core 不仅有 HTTP 层最多 3 次尝试，还包含结构化输出修复和 TypeScript 侧修复路径。一次用户操作不等于一次供应商调用；单看 Chat 接口成功率会低估失败和资源消耗。

core 部分请求可能不带 `max_tokens`，网关仍需有经过实测的默认输出上限。某别名无法满足预算/输出约束时，先不上架该模型，不能仅依赖客户端选项。

## 6. 发布和回退

1. 使用固定镜像和迁移版本部署测试环境；不开公众注册。
2. 先发放 1～3 个受限测试 Key，上传合成记录，验证全链路与 Key 撤销。
3. 导出 OpenAPI 契约快照，确认 core 与 admin 使用同一 v1 schema。
4. 备份并演练恢复后，再向实际 core 安装发放 Key，启用资料上传开关。
5. 发布失败可回退应用镜像；数据库迁移优先向后兼容，不假定所有 schema 都能自动降级。
6. 知识新版本失败回退发布指针；模型配置异常先停用别名或撤销 Key，再处理供应商问题。
7. 网关/业务后端升级先在测试环境重复核心契约用例，不自动跟随上游最新镜像。
