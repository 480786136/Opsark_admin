# Opsark_admin 第一期方案总览

状态：待实施。更新：2026-09-06。

## 1. 目标与边界

第一期将 Opsark_admin 做成独立服务，为 Opsark_core 提供知识资料沉淀和统一模型接入。产品先服务管理员管理的一组受信客户端，不建设面向公众的商业 SaaS。

### 必须交付

| 模块 | 一期交付 |
| --- | --- |
| 知识记录接收 | core 上传脱敏后的结构化任务记录，支持幂等和状态查询 |
| 资料整理 | 收件箱、模板生成草稿、编辑、来源关联、审核、发布和下架 |
| 知识库 | 多个库、标签、适用环境、版本、MD/TXT 导入、切片和向量索引 |
| 检索 | 按授权库检索，返回正文片段和来源引用；支持关键词降级 |
| 模型接入 | 供应商渠道、模型别名、允许模型列表、虚拟 Key、禁用/轮换、基本用量 |
| 最小管理基础 | 管理员登录、知识 Key 权限、操作审计、备份和任务重试 |
| core 对接 | 模型配置说明、记录上传和检索接口契约、联调用例 |

### 明确不做

注册/会员/充值/按量扣款/套餐/财务账本；个人长期记忆与自动记忆；多租户 SaaS 和团队角色体系；跨设备同步；PDF/OCR/网页爬虫/Git 自动同步；知识图谱、模型训练、独立聊天应用与可视化 Agent 工作流。

详细延期清单见 [后续功能待办](后续功能待办.md)。一期只保留必要扩展点，不提前创建这些功能的大量空表和占位页面。

## 2. 两个项目如何分开

| 责任 | Opsark_admin | Opsark_core |
| --- | --- | --- |
| 运行环境 | 服务端 Linux，浏览器管理界面 | Windows/macOS 桌面 |
| 模型 | 管理平台供应商与虚拟 Key | 保存用户自配 Key 或平台虚拟 Key，调用模型 |
| 知识 | 接收、审核、索引、检索 | 选择记录、脱敏、上传、展示引用、组装上下文 |
| 运维执行 | 不接触 SSH 会话，不执行客户端命令 | 保留 SSH、SFTP、审批和命令安全门禁 |
| 凭据 | 平台供应商密钥、管理会话、知识 Key 哈希 | SSH 密钥/密码、模型 Key、知识 Key 存系统钥匙串 |
| 版本 | 自己的仓库、依赖、构建和发布 | 保持独立版本，按 `/api/v1` 契约兼容 |

admin 先通过 HTTP 测试客户端和合成记录独立验收，再进入 core 联调。admin 开发不依赖 core 的源码或数据库。

现有 core 会在模型 endpoint 后追加 `/models`、`/chat/completions`，并使用 Bearer 认证。模型接入可以先作为一条普通模型配置使用，首期无需重做 core 账户中心。

## 3. 部署与调用关系

```text
core ── 模型虚拟 Key ──→ HTTPS /v1/* ──→ LiteLLM Proxy ──→ 模型供应商
  │                                          │
  │                                          └─ 独立 litellm 数据库
  └─ 知识 Key ────────→ HTTPS /api/v1/* ─→ FastAPI
                                              ├─ opsark_admin 数据库 + pgvector
管理员 ──→ Vue 管理界面 ──→ 管理 API            └─ 文档 Worker / 持久化附件目录
  └─ 受保护的模型控制台 ──→ LiteLLM 管理接口
```

一期运行单个 Caddy 入口、业务 API、Worker、PostgreSQL、LiteLLM 和静态前端。数据库可以使用同一实例内的两个数据库，但账号分开；业务服务不直接修改 LiteLLM 内部数据表。

LiteLLM 固定单副本、单 worker 才省略 Redis；增加 worker 或副本前必须配置共享 Redis 并验证限流和撤销一致性。业务 API 同样从单副本起步。

公众入口仅开放 HTTPS 与需要的健康检查。`/v1/models`、`/v1/chat/completions` 走模型路径白名单，禁止通过公网通配代理暴露 `/key/generate` 等控制接口。LiteLLM 管理入口仅在管理网络/VPN及管理员认证保护下开放。

一期允许知识管理和模型管理使用两个受保护的页面入口。知识页面自研，模型渠道与 Key 管理优先复用原生控制面。是否将模型管理封装进统一 Vue 页面是后续界面整合工作，不阻碍第一期交付。

## 4. 知识业务流程

### 4.1 上传记录和生成草稿

1. core 在任务完成或人工选择时，生成允许字段内的记录；用户查看即将上传的内容。
2. core 脱敏后提交记录；服务端执行格式、大小、授权范围、敏感模式检查。
3. 通过检查的记录以 `source_client_id + source_record_id + source_revision` 标识，同一上传重试不会产生新记录。
4. 持久化记录和草稿生成任务在同一数据库事务提交，返回 `202` 和 `record_id`。
5. Worker 将结构化字段整理为草稿：问题、环境、处理步骤、执行证据、结果、适用范围、注意事项、来源。
6. 管理员可以修改、合并多个来源、选择知识库和标签，然后审核发布。

一期默认模板整理，不为每次上传额外调用大模型。AI 润色/摘要为后续增强；这不影响“记录可整理成知识”的闭环。

允许失败任务进入收件箱，但必须标为失败案例；不能把有命令执行记录等同于处理成功。成功结论应引用真实结果/校验证据。

### 4.2 发布与版本

```text
记录：received → processing → ready_for_review → processed
                        └──→ failed（可重试）
                     管理员可将待审核记录标为 rejected

知识版本：draft → indexing → published → archived
                      └──→ failed（可重试）
```

- 接收记录成功不代表已入检索库，只有审核并索引完成的发布版本可检索。
- 编辑已发布知识会生成新草稿版本；旧版本继续可用，直到新版本索引完成后原子切换 `published_version_id`。
- 更新索引失败保留旧版本；不得先删除线上索引再尝试重新生成。
- 下架立即清除公开检索资格；异步清理物理索引不能延迟权限失效。
- 一期不缓存私有检索结果，减少下架与权限变更后的失效问题。

### 4.3 检索和引用

1. 从知识 Key 解析 `installation_id` 和允许知识库列表；不信任请求体中的归属标识。
2. 确定允许库、已发布版本、环境/软件等过滤条件。
3. 关键词检索、精确标识检索与向量召回并行，应用固定版本的融合排序。
4. 去重、限制每篇文档片段数和总返回大小，再次检查片段仍然可访问。
5. 返回片段、文档版本、来源记录、段落/行号和更新时间。

第一期小规模数据先使用授权集合内的精确向量检索，达到压测门槛后才增加 HNSW 等近似索引。Embedding 服务不可用时可降级为关键词，响应标明 `retrieval_mode=keyword_only`，不能假装语义检索正常。

中文查询使用应用层分词配合 PostgreSQL `simple` 全文配置；同时独立保存路径、命令名、错误码等精确标识。不得认为 PostgreSQL 默认全文配置自动提供高质量中文分词，也不得只靠忽略标点的模糊匹配区分路径。

一个索引版本固定 Embedding 模型、供应商、维度和切片策略。更换模型或维度必须重新构建影子索引并切换，不能混合比较不同模型的向量。Embedding 具体供应商通过一期样本评测确定，初版只支持一种索引配置。

默认切片保留标题层级和代码块；超长代码块按行切分并保留行号。初始目标约每片 400～800 tokens，重叠约 10%，同时受 Embedding 输入上限约束，实际值根据中文运维样本调整。

core 使用检索片段时，应展示引用，并在上下文中标为参考资料。资料中的命令不能自动执行，历史环境描述也不能替代当前服务器探测。

## 5. 模型接入与 Key

### 模型配置闭环

管理员配置上游供应商地址和凭据 → 声明模型别名与能力 → 运行兼容性测试 → 为客户端签发限定模型的虚拟 Key → 将 `base_url + api_key + model` 交给 core。

- 别名建议使用 `opsark-general` 等稳定名字；底层真实模型由控制面映射。
- 一期支持 core 使用的非流式 Chat Completions 和 `/models`；不承诺 Responses、音频、图片或任意 OpenAI 扩展端点。
- JSON 结构化输出必须逐模型验收。代理协议转换不能让不支持相应能力的模型自动变得支持。
- core 已有最多 3 次传输重试。网关初期关闭自动重试与跨模型故障切换，避免放大为多层重试；发生供应商状态不明时不承诺“恰好调用一次”。
- 传输重试之外，core 还有结构化输出修复调用；实际调用量按网关观测记录。core 未传输出上限时仍应用服务端上限，并保留真实 `finish_reason`，不能将截断标成成功结束。
- 每个客户端有独立模型 Key，可限制允许模型、撤销和设置有效期；具体限流/预算能力按锁定社区版本验证。
- 运营用量用于排障和控制供应商支出，不是用户账单；无 usage 时标为 unknown/estimated，不伪装成精确值。

### 凭据分工

| 凭据 | 管理方 | 用途 |
| --- | --- | --- |
| 上游供应商 Key | LiteLLM 服务端配置/受保护密钥存储 | 调用供应商，不下发 core |
| LiteLLM master key | 服务器密钥配置 | 控制面管理，不交给普通客户端 |
| 模型虚拟 Key | LiteLLM | core 调用模型，只授予必要模型权限 |
| 知识 Key | FastAPI | 上传记录/查询状态/检索，按库授权 |
| 管理员会话 | 管理 API | 审核发布和管理知识 Key，不用于模型调用 |

知识 Key 采用足够熵的随机值；只在创建时展示完整值，库中保存不可逆哈希、展示前缀、权限、有效期和禁用状态。core 将两类 Key 分别存入系统钥匙串。

管理员账户通过部署引导创建，不提供公众注册；密码哈希采用成熟实现，Cookie 会话要求 HttpOnly、Secure、SameSite，并保护修改操作免受 CSRF。不要把管理员口令写入前端构建产物。

## 6. 最小数据模型

| 表 | 核心内容 |
| --- | --- |
| `admin_accounts` / `admin_sessions` | 最小管理员身份、会话失效 |
| `installations` | 受信 core 安装标识、名称、状态 |
| `knowledge_api_keys` / `key_kb_grants` | 哈希、权限、允许库、到期和撤销 |
| `knowledge_bases` | 名称、描述、可用状态、索引配置 |
| `source_records` | 来源客户端/记录/修订、脱敏正文、哈希、处理状态 |
| `knowledge_documents` | 逻辑文档、当前发布版本、状态 |
| `document_versions` | 标题、正文、环境、软件、标签、版本和审核信息 |
| `document_sources` | 文档版本与一个或多个来源记录的关联 |
| `knowledge_chunks` | 文本、精确标识、全文索引、向量、位置和版本 |
| `processing_jobs` | 任务类型、幂等键、租约、重试次数和错误摘要 |
| `idempotency_requests` | Key 范围、请求哈希、资源 ID、过期时间 |
| `audit_events` | 操作者、动作、对象、结果、时间和请求 ID |

安装标识只是机器级归属，不伪装成团队租户体系。每条来源记录必须有归属；检索是否共享由知识库授权决定，不默认向所有客户端开放。

模型渠道、虚拟 Key 和用量由 LiteLLM 自己的数据库管理。若管理首页需要摘要，通过稳定管理 API 读取，不连接其内部表。

## 7. 可靠性与数据边界

- 记录写入和任务入队同事务。Worker 用租约、心跳、有限次数重试与人工重试入口，处理进程重启。
- 写文档/切片必须幂等，唯一键包含版本和片段位置；重复运行不能产生重复知识。
- 默认只上传明确选择的内容；不自动上传完整 SSH 输出、源代码树、开发者 JSONL 或 Key。
- 现有底层开发日志可能携带完整请求/响应；不能假定所有日志都经过同等脱敏。
- 服务端敏感检查只能降低风险，不能保证识别所有秘密。命中明确高风险模式时拒收且不保存原始敏感正文，错误只返回字段路径。
- 一期不做 URL 抓取，也不从客户端提交的任意地址下载文件，避免扩大出站访问范围。
- MD/TXT 渲染禁用原始 HTML或严格清理；禁止存储型脚本和不受限制的远程资源加载。
- 配置 Embedding 供应商时明确资料会传给谁；不满足资料外发要求的库不得启用该远程索引方式。
- 记录查询和引用获取按安装/知识库鉴权；知道 UUID 不代表拥有访问权。
- 操作日志默认只保存必要元数据、错误摘要和长度，模型原始提示词及回复不长期落盘。
- 备份业务数据库、LiteLLM 数据库和附件持久卷；上线前做恢复演练，避免“只备份向量不备份来源”。

## 8. 页面范围

知识管理提供：概览、记录收件箱、草稿编辑/来源对照、知识库列表、发布版本与索引状态、检索调试、知识 Key、操作审计。

模型入口提供：受保护的原生控制台入口、配置说明和调用示例。通过原生控制面完成供应商、模型和 Key 的管理；若锁定版本的 UI 不覆盖某项操作，使用受保护的管理 API 完成，不因此扩大一期自研范围。

检索调试页展示授权范围、命中片段和来源，不额外建设聊天窗口。
