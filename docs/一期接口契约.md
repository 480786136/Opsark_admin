# 一期接口契约：三个独立地址

更新：2026-09-07。以下为当前开发版接口；更完整的旧目标契约保存在 history，不能将其中未实现的字段视为已上线。

## 地址与凭据

| 调用方 | base URL 示例 | 凭据 |
| --- | --- | --- |
| core 模型调用 | http://127.0.0.1:4000/v1 | LiteLLM 模型虚拟 Key |
| core 上传/检索 | http://127.0.0.1:8002/api/v1 | knowledge 签发的限定库 Key |
| 管理员浏览器 | http://127.0.0.1:8001/api/admin/v1 | 平台 Cookie 会话 + 修改操作的 X-CSRF-Token |
| admin 服务端 | http://127.0.0.1:8002/internal/v1 | KNOWLEDGE_SERVICE_TOKEN + 已认证 X-Opsark-Actor |

示例是本机开发地址；远程 core 需填写可访问的实际地址，不是客户端自己的 localhost。服务 Token 与模型 master key 均不能交给 core。

## core 设置

配置知识接口 base URL、知识 API Key、目标库、记录上传开关与知识检索开关。两个开关默认关闭，单独控制；设置页应提供连通性检测和手动上传入口，方便开发者调试。Key 使用系统钥匙串，不保存到日志/localStorage。

## 公共知识接口

- GET /api/v1/knowledge/bases：当前 Key 授权的启用库。
- POST /api/v1/records：接收脱敏记录，返回 202、record_id、status、duplicate、status_url。
- GET /api/v1/records/{id}：只允许同安装标识查询处理状态。
- POST /api/v1/knowledge/search：返回发布片段、版本、来源和引用。
- GET /api/v1/knowledge/documents/{id}/versions/{version}：读取当前可访问发布版本；下架/旧版本返回 410。

所有公共业务请求采用 Authorization: Bearer 知识Key。Key 的 scopes 为 records:write、records:read、knowledge:read，同时受允许知识库限制。

上传请求示例（占位知识库 ID 需替换）：

```json
{
  "schema_version": "1.0",
  "source_record_id": "task-demo-1",
  "source_revision": 1,
  "knowledge_base_id": "REPLACE_WITH_KNOWLEDGE_BASE_ID",
  "record_type": "task_result",
  "title": "Nginx 检查案例",
  "occurred_at": "2026-09-07T00:00:00Z",
  "problem": "重载前验证配置",
  "steps": [],
  "outcome": {"status": "partial", "summary": "仅完成配置检查，未证明重载成功"},
  "redaction": {"client_applied": true, "ruleset_version": "core-upload-v1"}
}
```

上传头必须提供 Idempotency-Key，1～128 个可见 ASCII 字符。重试复用完全相同的序列化正文和 Key；同 Key 不同正文返回 409。同安装/source_record_id/source_revision 长期唯一。删除后留去重标记，重放返回 410。

正文不超过 256 KiB，未知字段拒绝。当前不接受压缩请求体（415）；检测到疑似秘密返回 422，不回显内容。精确字段由 knowledge/schemas.py 定义；仅允许白名单 DTO，不直接发送完整任务或 JSONL。

检索请求：

```json
{
  "query": "Nginx 配置检查",
  "knowledge_base_ids": ["REPLACE_WITH_KNOWLEDGE_BASE_ID"],
  "top_k": 5,
  "max_content_chars": 6000
}
```

结果含 retrieval_mode（keyword_only/hybrid）、index_version、hits、warnings。每个 hit 包含 document_id、document_version、content、citation。Top K 上限 10，总字符上限 12000；字符预算不等于 core Token 预算。

## 平台管理 API 与远程映射

平台对浏览器提供 /api/admin/v1/knowledge/{path}，将允许路径转为知识服务 /internal/v1/{path}。只支持代码白名单，不能任意转发 URL。

| path | 方法 |
| --- | --- |
| knowledge-bases | GET、POST |
| knowledge-bases/{id} | PATCH |
| knowledge-keys | GET、POST（完整 Key 仅创建时返回） |
| knowledge-keys/{id} | DELETE（撤销） |
| records | GET |
| records/{id} | DELETE（关联知识未删除时 409） |
| documents | GET、POST |
| documents/{id}/draft | PATCH，带 revision 乐观锁 |
| documents/{id}/publish | POST，带 revision，返回 202 和 job_id |
| documents/{id}/unpublish | POST |
| documents/{id} | DELETE |
| jobs | GET |
| jobs/{id}/retry | POST，仅失败任务 |
| search | POST |
| audit-events、health | GET |

knowledge 的 /internal/v1/openapi.json 由服务凭据保护，可取得实际 OpenAPI；平台不把它无条件公开。当前列表最多返回最近 200 项，分页和多来源合并尚待补齐。

## 模型协议

保持 /v1/models 和非流式 /v1/chat/completions。core 会在 endpoint 后拼接路径，因此填 base URL 而非完整 completions URL。需要 choices[0].message.content 字符串和真实 finish_reason；thinking 与 response_format 必须按实际供应商验证。

平台只是提供独立网关入口，没有实现自己的模型转发器。当前网关配置不证明任意供应商已经兼容，模型 Key 不能用于知识上传。

## 错误

知识错误使用 error.code/message/fields/retryable；平台错误使用 error.code/message。未认证 401、无权限 403、资源不可访问 404、修订冲突 409、已删除/下架 410、正文超限 413、字段/敏感检查 422、限流 429、依赖故障 503。
