# ADR-002：知识服务一期独立（修订）

创建：2026-09-07；修订：2026-09-08。状态：独立知识 Web/管理鉴权及 Admin 受限模型适配器已实现，开发测试通过，生产与真实上游待验收。

## 修订原因

此前“知识后端独立、管理页面统一放 Admin”的实现只完成部署和数据拆分，不符合两个独立系统的要求。“模型网关入口”也不能替代一期的多供应商 API 配置、实际转发和监控。

## 决策

- Opsark_knowledge 独立拥有管理页面、管理鉴权、知识 Key、上传、整理、审核、发布、检索、Worker 和知识数据库。
- Opsark_admin 负责第三方 API 配置、对外模型映射、模型用户 Key、实际转发和监控；后续承载用户中心与计费。不管理知识资料。
- core 分别配置知识与模型 base URL/Key，互不混用。
- 两个服务独立安装、启动、升级、备份，不共享 ORM、跨库 join 或把对方登录/服务作为必需依赖。
- 知识一期提供本地管理账号，不建设公众注册。未来统一登录可以选配，但不能破坏独立运行；外部主体通过标识映射，不建跨库外键。
- 知识整理可配置外部模型 API，Admin 转发接口可以作为选项，不能是唯一必需上游。无 Embedding 仍支持明确的关键词模式。

## 现状与迁移

已实现平级项目、独立 API/Worker/数据库、知识业务及 core 公共接口。平台数据库目前只有管理员与会话。

知识已具备独立 Web/本地会话，Admin 已提供渠道配置、模型路由、用户模型 Key、JSON/SSE 兼容转发和调用记录。旧 Admin 知识页面已移除，旧代理对管理员返回 410，不再调用知识服务。

迁移先新增知识管理入口和账号初始化，验证 core 公共接口兼容，再退役 Admin 知识页面、代理及配置依赖。不能先删入口导致资料无人管理，也不能默认复制密码、会话或共享高权限 Token。

本次新增增量迁移，但不自动升级用户数据库、覆盖 .env、复制密码或撤销用户凭据。端口仍为 Admin 8001、知识 8002；模型接口为 Admin /v1。管理员需备份后执行各项目迁移，再初始化知识账号/构建页面。详见 [开发版说明](独立系统开发版使用与验收.md)。

## 安全与验收

现有 /internal/v1 仅供可信服务 Token 访问，不能公开给 core 或将 Token 放进浏览器。目标知识管理采用自身会话、CSRF 和权限；具体新路径实施时确定。

- 停止 Admin：知识可独立登录、建库、签发 Key、上传、整理、审核、发布、检索。
- 停止知识：Admin 可配置供应商、签发模型 Key、转发请求、显示监控。
- 不共享数据库、管理 Cookie 或必需服务 Token；core 两类 Key 相互拒绝。
- 资料、来源、版本、去重信息在迁移后可追溯。
- 开放多人使用前完成主体/空间和资源权限隔离；现有 scope/允许库不是完整多租户。

长期约束见 [知识服务长期演进](../../Opsark_knowledge/docs/知识服务长期演进.md)。
