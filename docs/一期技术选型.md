# 一期技术选型（2026-09-08 修订）

状态：已实现知识独立 Web/管理鉴权和 Admin 内置受限 Chat Completions 适配器。Admin 数据库唯一持有渠道/路由/Key，单进程限流，Fernet 加密上游 Key；cryptography 版本锁定于 constraints.txt。真实供应商和生产 PoC 尚未完成，实际状态见 [开发版说明](独立系统开发版使用与验收.md)。LiteLLM 仅保留实验模板，不是当前运行依赖。

## 是否从零开发

不推倒已有知识入库、任务、审核和版本代码。沿用 Vue、FastAPI、SQLAlchemy，自研所需业务。

模型采用“Admin 管理业务 + 可替换适配器”边界。本轮先实现受限兼容协议，便于管理/转发/监控形成可测闭环；双模拟供应商通过，但真实供应商 PoC 仍是发布门槛。不是任意协议转换器，若新增供应商原生协议再比较复用引擎或独立适配，不能宣称省略 PoC 即完成商业接入。

结构化正文继续存数据库；文件导入时再设计对象存储。多副本前补共享限流，不能把单进程内存限流当全局额度。

## 模型引擎 PoC 门槛

至少验证两家目标供应商：配置启停、模型映射、用户 Key 隔离/撤销/限流、JSON、SSE、取消、超时、429/5xx、usage 缺失和错误脱敏。Admin 应能通过所选版本的接口完成业务管理，不要求用户转到原生控制台。

明确渠道、Key、限额与用量的唯一权威来源，避免 Admin/引擎配置漂移。先显式选路由，不承诺复杂负载均衡；流式已输出或结果不确定时不盲目重试，避免重复生成/费用。真实探测需开发凭据和预算。

## 知识可演进性

内容版本与索引构建分开，任务绑定模型、维度、切片规则、指纹并校验 Worker 配置。换维度必须迁移/重建，不能仅改 .env。历史迁移采用固定版本定义，不随当前 ORM 漂移。详见 [长期演进](../../Opsark_knowledge/docs/知识服务长期演进.md)。

## 商业化与生产门槛

不部署模型权重、不要求 GPU。外部模型/Embedding 产生费用和资料外发，启用前需明确授权与预算。

技术选型不等于许可验收。最终引擎版本、企业功能边界、依赖许可证及上游 API 转发/转售条款在接入前单独核验；旧许可记录不是无限期商用保证。参考入口：[LiteLLM 许可](https://github.com/BerriAI/litellm/blob/main/LICENSE)、[pgvector](https://github.com/pgvector/pgvector)。

生产前锁定依赖/镜像、TLS、凭据轮换、上游 URL 限制与 SSRF 防护、日志保留及恢复演练。本次不改变依赖、实际凭据或 .env。
